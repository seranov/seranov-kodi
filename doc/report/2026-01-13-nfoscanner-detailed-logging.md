# NFO Scanner: Detailed Logging Implementation

**Дата:** 2026-01-13  
**Плагин:** service.seranov.nfoscanner  
**Версия:** 1.1.1 → 1.1.2

## Описание задачи

В плагине nfoscanner необходимо было реализовать подробное логирование для отладки и мониторинга работы сервиса. Требования:
1. Логирование начала и окончания обработки каждой папки
2. Вывод подробного описания исключительных ситуаций
3. Логирование различной важной для отладки информации

## Выполненные изменения

### 1. Добавлен импорт модуля traceback

Добавлен импорт `traceback` для вывода полных стек-трейсов исключений:

```python
import traceback
```

### 2. Улучшенное логирование в методе `scan_folder()`

Добавлено детальное логирование обработки папок:

#### Логирование начала обработки:
- Логируется начало сканирования папки с разделителем для визуальной читаемости
- Выводятся родительские жанры
- Замеряется время начала обработки

```python
start_time = time.time()
self.log(f'=== Starting scan of folder: {path} ===', xbmc.LOGINFO)
self.log(f'Parent genres: {parent_genres}', xbmc.LOGDEBUG)
```

#### Логирование окончания обработки:
- Выводится статистика обработки папки:
  - Длительность обработки в секундах
  - Количество реимпортированных фильмов
  - Количество обработанных подпапок
  - Наличие movie.nfo и category.nfo
  - Найденные жанры из category.nfo

```python
self.log(f'=== Completed scan of folder: {path} ===', xbmc.LOGINFO)
self.log(f'Folder scan statistics:', xbmc.LOGINFO)
self.log(f'  - Duration: {duration:.2f} seconds', xbmc.LOGINFO)
self.log(f'  - Movies re-imported: {scanned_count}', xbmc.LOGINFO)
self.log(f'  - Subdirectories processed: {subdirs_count}', xbmc.LOGINFO)
```

### 3. Улучшенное логирование JSON-RPC запросов

Все запросы к Kodi API теперь логируются (в режиме DEBUG):
- Запрос в формате JSON
- Ответ от API
- Результаты обработки

Это позволяет отслеживать взаимодействие с базой данных Kodi.

### 4. Подробное логирование исключений

Во все блоки `except` добавлен вывод полного traceback:

```python
except Exception as e:
    self.log(f'Error description: {e}', xbmc.LOGERROR)
    self.log(f'Error traceback: {traceback.format_exc()}', xbmc.LOGERROR)
```

Это применено в следующих методах:
- `load_settings()` - ошибки загрузки настроек
- `get_video_sources()` - ошибки получения источников видео
- `get_folder_mtime()` - ошибки получения времени модификации папки
- `read_category_nfo()` - ошибки чтения category.nfo
- `get_movie_nfo_mtime()` - ошибки получения времени movie.nfo
- `get_kodi_movie_date()` - ошибки запросов к БД Kodi
- `reimport_movie()` - ошибки реимпорта фильма
- `get_movie_id_by_path()` - ошибки поиска ID фильма
- `add_genres_to_movie()` - ошибки добавления жанров
- `scan_folder()` - ошибки сканирования папки
- `scan_all_sources()` - ошибки сканирования источников
- `run_scanner()` - ошибки основного цикла сканера

### 5. Расширенное логирование операций с БД

#### Поиск и удаление фильмов:
- Логируется поиск существующего фильма в БД
- Логируется ID найденного фильма
- Логируется процесс удаления

#### Реимпорт фильмов:
- Логируется начало реимпорта
- Логируются дополнительные жанры
- Логируется запуск VideoLibrary.Scan
- Логируется результат операции

#### Работа с жанрами:
- Логируются текущие жанры фильма
- Логируются новые жанры для добавления
- Логируется результат обновления

### 6. Улучшенное логирование scan_all_sources()

Добавлен развернутый вывод информации о процессе сканирования:

```
======================================
=== Starting full sources scan ===
======================================
Total scan duration: XX.XX seconds
Total sources scanned: X/X
Failed sources: X
Total movies re-imported: X
======================================
```

Для каждого источника:
- Время начала и окончания обработки
- Длительность обработки
- Количество реимпортированных элементов
- Ошибки, если они возникли

### 7. Улучшенное логирование основного цикла

В методе `run_scanner()`:
- Логируется запуск цикла сканера
- Периодически выводится время до следующего сканирования
- Логируется начало каждого цикла сканирования
- Логируется состояние паузы
- Логируется завершение цикла

### 8. Детальное логирование обработки NFO файлов

#### movie.nfo:
- Логируется наличие файла
- Логируется дата модификации
- Сравнение с датой в БД Kodi
- Решение о необходимости реимпорта

#### category.nfo:
- Логируется чтение файла
- Размер содержимого
- Каждый найденный жанр
- Итоговый список жанров

### 9. Логирование сетевых источников

При обработке источников видео:
- Логируется каждый найденный источник
- Логируется пропуск сетевых источников (если опция отключена)
- Логируется трансляция путей

## Уровни логирования

Используются следующие уровни логирования:

- **DEBUG** - детальная отладочная информация:
  - JSON-RPC запросы и ответы
  - Информация о времени модификации файлов
  - Детали обработки каждой папки
  - Информация о поиске в БД

- **INFO** - важная информация о процессе:
  - Начало и окончание обработки папок
  - Статистика сканирования
  - Успешные операции реимпорта
  - Найденные жанры

- **WARNING** - предупреждения:
  - Файлы не найдены в ожидаемых местах
  - Операции завершились не полностью
  - Прерывание сканирования

- **ERROR** - ошибки:
  - Исключения с полным traceback
  - Критические ошибки сканирования
  - Ошибки работы с БД

## Преимущества изменений

1. **Полная прозрачность работы** - теперь можно отследить каждый шаг работы сканера
2. **Упрощенная отладка** - traceback'и позволяют быстро найти источник проблемы
3. **Мониторинг производительности** - логируется время обработки каждой папки и источника
4. **Статистика работы** - можно увидеть, сколько фильмов было обработано
5. **Контроль за JSON-RPC** - все запросы к Kodi API видны в логе (при включенном DEBUG)

## Тестирование

Код проверен на синтаксические ошибки с помощью `python3 -m py_compile`.

## Инструкции по использованию

1. Для базового логирования установите опцию `debug_logging = false` в настройках плагина
   - Будут логироваться только важные события (INFO, WARNING, ERROR)
   
2. Для подробного логирования установите опцию `debug_logging = true`
   - Будут логироваться все детали работы, включая JSON-RPC запросы

3. Лог-файл находится в профильной директории плагина: `scanner.log`

4. Просмотреть лог можно через встроенный инструмент просмотра логов плагина

## Обратная совместимость

Все изменения полностью обратно совместимы. Добавлено только логирование, логика работы плагина не изменена.
